# 1. Use Flask for the HTTP layer

Date: 2026-09-02

## Context

The items service needs an HTTP API with three routes, API-key authentication, and JSON responses. The team of three has shipped Flask services before and has no experience with async frameworks. Request volume is a few hundred per minute, served from one container. Candidates were Flask, FastAPI, and Django.

## Decision

We use Flask 3.1 for the HTTP layer, with routes defined in `app.py` and no extensions beyond the standard library.

## Status

Accepted

## Consequences

Routes stay small and readable, and every team member can review changes without learning a new framework. Flask has no built-in request validation, so each route validates its own input. Moving to an async framework later means rewriting the route layer; the data layer behind it is unaffected.
